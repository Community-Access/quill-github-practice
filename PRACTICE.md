# Practice exercises

There's one exercise for each chapter of the GitHub Guide, in the order the
guide teaches them. **Here** means you can do it in
`Community-Access/quill-github-practice` itself. **Your copy** means you need
a copy of your own, made from this template and set up with the Set up
practice workflow (see the README).

Most exercises name the issue or pull request by its title rather than its
number, because the numbers in your copy may differ.

## Chapter 1: Getting started (here)

1. Sign in with Manage GitHub Accounts. In QUILL it's on File > Open from
   Remote. In QUILL Lite it's File > Manage GitHub Accounts.
2. Open GitHub Items and choose this repository.
3. Find the issue "Word count is off by one when text ends with a space" and
   read it from the top.

## Chapter 2: Getting around (here)

1. In GitHub Items, move between the Issues and Pull requests lists.
2. Filter the issues by the label `good first issue`. There should be one.
3. Open "Add a line count to the summary" and move from comment to comment.
   Then go back to the list without losing your place.

## Chapter 3: Your inbox and your work (here)

1. Subscribe to the issue "Question: what counts as a word?".
2. Ask someone to reply there, or reply yourself from a second account, then
   find the notification in your inbox and mark it Done.
3. Look at My Work. Anything you've commented on in this repository should be
   there.

## Chapter 4: Issues (here, then your copy)

Here:

1. Read "Question: what counts as a word?" and hear the summary of the
   discussion.
2. Add a reaction to its first comment.
3. Write a new issue using the **Bug report** template. Say what you tried and
   what happened. It doesn't have to be a real bug.

In your copy:

1. Add the label `accessibility` to "The README should explain how to run the
   tests".
2. Put the bug issue in the milestone "Practice milestone 1".
3. Close "Typo in the module docstring" and then reopen it.
4. Select three issues and add the `question` label to all of them at once.

## Chapter 5: Pull requests and review (here, then your copy)

Here:

1. Open the pull request "Add a line count". Hear its one-sentence summary.
2. Open it in the review window. Move through the outline, then from thread
   to thread.
3. Find the suggested change on `line_count`. Read what it would change.

In your copy:

1. Reply to the review thread, then resolve it.
2. Comment on a single line of the diff, then on a range of lines.
3. Apply the suggested change, then merge the pull request.
4. Mark the draft pull request "Speed up word counting" as ready for review.

## Chapter 6: Actions and checks (here, then your copy)

Here:

1. Open the draft pull request "Speed up word counting". Its check fails.
2. Use What Failed. It should name the failing test, `test_counts_hyphenated_words`,
   and quote the assertion.
3. Read the job log, step by step.

In your copy:

1. Run the **Tests** workflow by hand on `main`. It should pass.
2. Rerun the failed jobs on the draft pull request. They'll fail again, which
   is the point.
3. Cancel a run while it's still going, then delete it.

## Chapter 7: Code and repositories (here)

1. Browse the files. Open `src/tally/__init__.py`.
2. Look at the blame for that file. You'll hear who changed which lines, in
   runs.
3. Search the code for `def word_count`.
4. Open the release `v0.1.0`, read its notes and download its attached file.

## Chapter 8: Discussions and security (here)

1. Open the discussion "Welcome: say hello and ask anything" and read the
   thread.
2. Reply to it. Tell us which editor you're using, if you like.
3. Read the security policy. There are no security alerts here, so
   Security Alerts should tell you so.

## Chapter 9: Codespaces and the command line (your copy)

1. Create a codespace on your copy, then stop it and delete it. Codespaces
   counts against your free monthly hours, so don't leave it running.
2. If you have the GitHub command-line tool, clone your copy and push a small
   change to a new branch.

## Chapter 10: Troubleshooting (here)

1. Open Manage GitHub Accounts and check which account is active.
2. Look at the rate-limit readout. Reading this repository uses very little of
   it.

## Chapter 11: Keyboard reference

There's nothing to do here. Keep chapter 11 open while you work through the
others, and give a key to any command you find yourself using often.
